01 — Overview

Project Aims

Four primary goals that drive every design and engineering decision in this ecosystem.

1

Bridge the Communication Gap

Create synchronized real-time portals for Clients, Senior Advocates, and Junior Advocates — ensuring every stakeholder stays informed and connected at all times.

2

Automate Routine Overhead

Offload repetitive document drafting tasks using generative AI (Gemini) and automate client hearing alerts via background notification schedulers.

3

Ensure Reliable Case Reminders

Keep clients and assigned advocates updated about court dates dynamically with automated email notifications sent at 5-day, 2-day, and 1-day intervals before hearings.

4

Enforce Dynamic Security

Provide a real-time editable roles and permissions matrix allowing granular access management at a module-specific level for all three user roles.

02 — Architecture

Core Technology Stack

A lightweight, modern web architecture designed for secure, real-time legal operations.

⚛️

Frontend

Next.js (React)

Tailwind CSS v4 and Lucide Icons providing a modern, responsive, user-friendly interface for dashboards and legal management modules.

🐍

Backend

FastAPI (Python)

Asynchronous routing and SQLAlchemy ORM enabling high-performance API development, efficient request handling, and scalable backend operations.

🗄️

Database

MySQL

Configured with connection pooling, automated schema validation, and migration helper scripts to ensure reliable data storage and integrity during application startup.

🤖

AI Drafting Engine

Gemini Flash

Google Gemini API (gemini-flash-latest) integrated to generate legal drafts, pleadings, notices, and provide AI-assisted document drafting for advocates.

🔐

Security & Auth

JWT + Bcrypt

JWT for secure authentication, Passlib/Bcrypt for password hashing, and a dynamic role-based permission system supporting all three access tiers with protected routes.

⏰

Scheduler & Notifications

APScheduler + SMTP

Background worker configured to execute scheduled tasks and automatically send hearing reminders and case notifications through Google SMTP email services.

🏛️

eCourts Integration

CNR / Research

System architecture designed to support eCourts India case retrieval using the 16-character CNR (Case Number Record), with database schema and UI prepared for future live API integration.

🐳

Deployment

Docker + Compose

Dockerized application using Dockerfile, docker-compose.yml, and docker-compose.dev.yml for simplified development, testing, and production deployment across multiple environments.

04 — Core Workflows

Three Core Workflows

End-to-end processes that define how legal work flows through the system from creation to notification.

1

Case Creation & Consultation Scheduling

1

The Senior Advocate creates a new case by entering client information, case details, uploading relevant documents, and assigning the case profile within the system.

2

When a case discussion is required, the Senior Advocate or Client can schedule a consultation by selecting a preferred mode — Video Call, Face-to-Face Meeting, or WhatsApp Chat.

3

The system supports booking, rescheduling, and updating consultation statuses while automatically synchronizing the calendar and sending notifications to relevant users.

2

Case Assignment & Hearing Management

1

The Senior Advocate registers a new case, assigns the client, uploads case documents, and records hearing details and important case information.

2

The Senior Advocate assigns the case to a Junior Advocate by specifying assignment details, priority level (High, Medium, or Low), and work instructions.

3

The assigned case is automatically reflected in the Junior Advocate's dashboard, while hearing schedules are synchronized with the calendar and notification system.

3

Automated Hearing Reminders & Notifications

1

The Senior Advocate updates hearing dates, case status, and other important information through the Case Management dashboard.

2

The APScheduler background service performs scheduled daily checks to identify upcoming hearings and important case milestones.

3

The system automatically sends responsive HTML email notifications to the registered client and assigned Junior Advocate at 5-day, 2-day, and 1-day intervals before the scheduled hearing.
